# dsh-agent-team-policy

一个 DeepSeek Harness（`dsh`）插件：约束**什么时候才允许起子智能体**，而不是让 harness 自带的"默认后台起子、并行起子"成为上下文里唯一的规则。

只注入一段系统提示词。没有工具、没有服务、没有依赖。

## 为什么

只有两件事值得开一个新上下文：

1. **对抗性审查。** 模型在同一个上下文里审查自己的产出，会倾向于确认既有判断。看不到推理过程、并被要求以证伪为目标的审查者，才有机会找到反例。
2. **一次性上下文。** 检索大型代码库、读长日志会把主循环撑爆。把阅读发出去，只要回摘要、证据位置和未决问题，不要原始材料。

其余情况——小改动、必须先看到源码才能决定的事、你已经想清楚的事——都留在主循环里做。

## 注入了什么

一段 `delegation:policy`，顺序 `100`：

- 在人设（`0`）之后；
- 在 plan mode（`500`）、Agent Teams 策略（`600`）和所有工具段（`1000+`）之前；
- 所以它先于任何"默认后台起子"的工具引导被读到。

正文只放行上面两种情况，列出必须自己完成的情形（单文件小改、必须先看原始材料、说不出独立可验收的产出、结论已想清），并要求每次委派写清目标、验收标准、写作用域、是否需要本会话上下文；并行时写作用域不重叠，能复用就不新起，不凑数；并要求每次委派前先跟用户确认——除非用户明确要求，否则不要自动发起。

## 安装

```sh
dsh plugin add dsh-agent-team-policy
```

从本地目录安装：

```sh
dsh plugin add /绝对路径/dsh-agent-team-policy
```

也可以在应用的插件页里把这个目录当 bundle 装。装完不需要任何配置：bundle patch 挂一个宿主插件，插件注册一段 section。

## 验证

开一个新会话，让 agent 复述它的委派规则；或者给一个单文件小改，看它是否还会起子。section 出现在组装后的系统提示词里，并且会被会话派生的每个子智能体继承——孙子代理同样受这套规则约束。

## 边界

- **是引导，不是强制。** 它拦不住一次 `subagent` / `spawn_teammate` 调用；真正要硬上限，仍然用工具配置里的 `maxDepth`、`toolFilter`。
- **是追加，不是替换。** `@deepseek-ai/dsh-tool-subagent` 自带一段仍写着"默认后台"的引导；本插件的正文明确声明优先于它。
- **会被 `complete: true` 的 preset 丢掉。** 整份重写系统提示词的 preset（内置的 `minimal` 就是）只保留自己的人设。
- **规则正文是中文。** 改措辞或改语言就编辑 [`lib/index.js`](lib/index.js) 里的 `POLICY`；插件刻意不带 config schema，既没有要校验的字段，也不会因为未知配置项挂载失败。

## 兼容性

按 dsh `0.2.2-rc.1` 编写，只用到 `ctx.systemPrompt.section({ name, order, text })`。任何暴露 `systemPrompt` 服务的版本都能用。
